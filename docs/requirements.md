# 상품 소싱 도구 요구사항 정의서

작성일: 2026-09-30. 상태: 설계 v1. 구현·실연동·발주자 검수 완료를 의미하지 않는다.

이 문서는 1인 사업자가 상품 URL을 입력하고 수집 결과와 AI 생성물을 검토한 뒤 판매 채널에 등록하는 도구의 개발·검수 기준이다. 확정된 우선순위는 수집, AI 생성, 채널 등록 순이다. 내부 동작은 아래 설계로 개발하고, 외부 규격과 계정 조건은 [확인 목록](channel-fields.md)을 해소한 뒤 실연동한다.

## 범위와 우선순위

| 구분 | 범위 | 검수 조건 |
| --- | --- | --- |
| P0 수집 | 도매꾹 필수, 오너클랜 확장, 원본 보존, 수집 결과·목록 | 두 소싱처가 같은 Product 계약을 사용한다 |
| P0 생성 | 채널별 상세페이지, 썸네일 3안, 수정·확정, 비용 상한 | 사람이 확인한 콘텐츠만 등록할 수 있다 |
| P0 등록 | 쿠팡 먼저, 스마트스토어 다음, 검증·이력·수동 재시도 | 채널 실패가 다른 채널을 막지 않는다 |
| P0 운영 | 단일 비밀번호 인증, Docker, 백업·복구, 한국어 문서 | 다른 PC에서 실행하고 백업을 복원할 수 있다 |
| P1 선택 | 후보 검색·기본 필터·비용 반영 잔액, 세 번째 소싱처 | P0 수집·생성이 완료된 뒤 착수한다 |
| 보류 | 수동 입력 | 요청 스키마만 설계한다. 저장 API·입력 화면은 구현하지 않는다 |
| P2 또는 제외 | 고급 추천, 가격·재고 동기화, 주문, 대량 처리, 멀티유저 | 1차에 구현하지 않는다 |

등록 일정이 부족하면 채널 규격 검증과 등록용 파일 내보내기로 축소한다. 내보내기 형식도 공식 규격이나 사람이 사용하는 양식 확인 후 결정한다. 확인되지 않은 파일을 업로드 가능하다고 표시하지 않는다.

## 상품 수집

| ID | 요구사항 | 검수 방법 |
| --- | --- | --- |
| COL01 | URL의 실제 호스트를 검사해 레지스트리에서 소싱처를 고른다 | 지원·미지원·유사 도메인 fixture 검증 |
| COL02 | API 이용 조건 확인 후 API를 우선 사용한다. 브라우저 대체는 동시 1개, 요청 간격 2초 이상이다 | fake 호출 기록으로 간격·동시성 확인 |
| COL03 | 상품명, 도매가, 옵션, 재고, 이미지, 상세 HTML, 배송 조건을 표준화한다 | 소싱처별 normalize 스냅샷 비교 |
| COL04 | 미수집 값은 null로 보존한다. 미확인 재고와 재고 0, 미확인 배송비와 무료배송을 구분한다 | 누락·품절·무료배송 fixture 비교 |
| COL05 | 인증정보를 제외한 상품 응답 원본은 products.raw에 보존한다. 재수집은 새 레코드를 만든다 | 같은 URL 재수집 후 이전 raw가 유지됨 |
| COL06 | 부분 수집과 정규화 실패도 원본·누락 필드·사유를 남긴다 | 원본이 있는 정규화 실패에서 Product 레코드가 남음 |
| COL07 | 이미지 다운로드 일부 실패 시 수집 상품을 유지하고 경고한다 | 실패 이미지 URL과 상태를 화면에서 확인 |
| COL08 | 실패 시 원본 링크와 재시도 방법을 안내한다. 로그인·CAPTCHA·접근 거부는 중단한다 | 우회나 자동 반복 요청이 없음 |
| COL09 | 최근 수집 목록과 소싱처·수집 상태 필터를 제공한다 | complete·partial·failed 항목 조회 |

수집 이미지는 허용된 외부 URL만 내려받는다. 로컬·사설망 주소와 해당 주소로의 리다이렉트는 차단한다. 파일 형식·크기 제한은 내부 설정으로 관리한다. 수집 HTML은 raw에 보존하되 화면 미리보기와 생성 콘텐츠에는 정제된 HTML만 사용한다.

## 생성과 사람 확인

| ID | 요구사항 | 검수 방법 |
| --- | --- | --- |
| GEN01 | 생성 전 상품명·사용 가능한 상품 정보·이미지 사용 조건을 검사한다. 누락된 가격·재고는 생성하지 않는다 | 불완전한 fixture로 차단 또는 경고 확인 |
| GEN02 | 텍스트·이미지 호출은 adapters/ai에서만 수행하고 프롬프트는 파일로 관리한다 | 코드 구조 검사 |
| GEN03 | 제품 특성·인증·효능을 원본 근거 없이 추가하지 않는다. 타사 브랜드·로고·캐릭터를 생성 이미지에 넣지 않는다 | 샘플 생성물 사람 검수 |
| GEN04 | 상품당 썸네일 3안을 생성하고 채널별 형식 변환본을 만든다 | 3안 선택과 채널별 미리보기 확인 |
| GEN05 | 채널별 제목·상세·썸네일·판매가·카테고리·옵션·배송·고시정보를 검토·수정한다 | 저장 후 동일 값 재조회 |
| GEN06 | 생성 결과는 draft다. 확인 버튼은 현재 content_version을 확정한다 | 확정하지 않은 등록 요청을 서버에서 거부 |
| GEN07 | 등록 대상 필드 변경이나 재생성은 draft로 되돌리고 확정 정보를 해제한다 | 확정 → 수정 → 등록 거부 → 재확정 |
| GEN08 | 한 채널 생성 실패 시 성공 채널의 draft와 성공한 자산을 보존한다 | fake AI로 부분 실패 확인 |
| GEN09 | 호출마다 일·월 예산을 원자적으로 예약하고 실제 사용량을 기록한다 | 동시 요청 합계가 한도를 넘지 않음 |

AI 비용은 KRW 기준 내부 예산으로 제안한다. 실제 한도·공급자·모델·환산 기준은 확인 목록에서 결정한다. 설정이 없거나 비용 상한을 계산할 수 없으면 유료 호출을 거부한다. 공급자 과금이 불명확한 호출은 예약액을 유지한다. 자세한 예약·정산 규칙은 [어댑터 계약](adapter-contracts.md)에 둔다.

## 등록과 이력

| ID | 요구사항 | 검수 방법 |
| --- | --- | --- |
| REG01 | status=confirmed이며 content_version=confirmed_version인 경우에만 등록한다 | 직접 API 요청에서도 검사 |
| REG02 | 실연동 여부·필수 정보·이미지·카테고리 규격을 사전 검증한다 | 미확인 필수 규격이 있으면 실등록 거부 |
| REG03 | 실계정 등록은 사람이 화면에서 실행한 요청으로만 시작한다 | 생성·확정·서버 재시작에서 등록이 실행되지 않음 |
| REG04 | 등록 시도마다 대상 버전·요청·응답·결과·시각을 보존한다 | 두 번 시도하면 별도 이력 두 건 |
| REG05 | 실패 후 listing은 confirmed를 유지한다. 수정 없이 다시 시도하거나 수정 후 재확정할 수 있다 | failed 이력에서 수동 재시도 |
| REG06 | 응답 유실·전송 여부 불명확 시 unknown으로 기록하고 재등록을 막는다 | 외부 등록 여부를 사람이 확인할 때까지 중복 호출 없음 |
| REG07 | 두 채널 실행은 채널별 결과를 기록한다. 한 채널 실패 뒤 다른 채널을 계속 처리한다 | fake 채널로 성공·실패 혼합 확인 |
| REG08 | mock 결과는 simulated다. 실상품 ID·실등록 완료 상태를 만들지 않는다 | 화면·DB에서 실등록과 구분 |
| REG09 | 실등록 성공한 listing의 재등록·수정은 1차에서 막는다 | 이력 조회만 가능, 수정 등록은 P2 |

## 운영과 보존

기본 인증은 헬스체크를 제외한 API·자산 다운로드에 적용한다. 운영에서는 HTTPS로 제공한다. API 키·비밀번호는 env 또는 암호화 설정에만 두고 UI는 저장 여부만 표시한다. 요청·응답 기록에는 Authorization, 서명, 토큰, 비밀번호를 저장하지 않는다.

백그라운드 작업은 PostgreSQL jobs와 단일 프로세스 BackgroundTasks로 시작한다. 자동 외부 재시도와 Redis는 사용하지 않는다. 재시작으로 중단된 작업은 화면에 표시하고 사람이 다시 시작한다. 등록 전송 여부가 불명확하면 REG06을 적용한다.

## 비용 표시

화면의 기존 마진 표시는 비용 반영 잔액으로 정의한다. 단품 기준 잔액 = 판매가 + 구매자 배송비 − 도매가 − 소싱 배송비 − 판매자 부담 발송비 − 채널 수수료 − 추가 입력 비용이다. 수수료 부과 기준은 채널별 확인값을 사용한다. 묶음배송·옵션별 원가가 다른 경우 단일 값을 확정값으로 보여주지 않는다.

값이 빠지면 잔액과 비율은 null이다. 잔액률의 분모는 판매가이며 판매가가 0이면 계산하지 않는다. 세금·광고·반품 등 미반영 비용을 함께 표시하고 순이익으로 부르지 않는다.

## 설계 완료와 구현 검수

이 문서와 [화면 설계](screens/README.md), [DB 설계](db-schema.md), [어댑터 계약](adapter-contracts.md), [규격 확인 목록](channel-fields.md)의 상태·필드·범위가 일치하면 설계 v1 작성 완료다. 실제 API 승인과 발주자 화면 검수는 별도 TASKS 항목으로 유지한다.

구현 PR은 make lint와 make test를 통과한다. 어댑터는 fixture 스냅샷, 서비스는 fake Protocol, 상태·비용 동시성은 DB 통합 테스트로 검증한다. 테스트에서 실제 네트워크·유료 생성·상품 등록은 하지 않는다.
